# Enginewright v0.3.0

Early preview. Supported: **Unreal Engine 5.8, Windows (Win64)**. Other engine versions, Mac and Linux are not tested yet.

## Download

| File | SHA-256 |
|---|---|
| `Enginewright-0.3.0-UE5.8-Win64.zip` | `@SHA256@` |

Check it in PowerShell with `Get-FileHash .\Enginewright-0.3.0-UE5.8-Win64.zip` (or `sha256sum -c Enginewright-0.3.0-UE5.8-Win64.zip.sha256`).

## Install

1. Close the editor. Unzip into your project's `Plugins/` folder, so you get `<YourProject>/Plugins/Enginewright/Enginewright.uplugin`.
2. Open the project. The Output Log prints `Enginewright: MCP server on http://127.0.0.1:3100/mcp`.
3. Connect your client with the ready-to-paste config in `<YourProject>/Saved/Enginewright/clients/` (Claude Code, Codex, Cursor, VS Code, Hermes).
4. Ask your agent to call `doctor`.

Works in Blueprint-only and C++ projects. No Python, Node or other runtime is needed.

## New since v0.2

- **UMG**: `widget_create`, `widget_tree`, `widget_get`, `widget_add` (widget, properties and slot layout in one checked call), `widget_set`, `widget_remove`, and `widget_render` (a Widget Blueprint to PNG at any resolution, no Play In Editor needed).
- **Runtime UI with CommonUI support**: `ui_state` lists what a player's screen shows (widgets in the viewport, CommonUI activatable widgets and stacks, visible buttons with label, selected state and rectangle); `ui_click` clicks by name or label and refuses a button that another widget covers; `ui_open` / `ui_close` show one screen in Play In Editor, or push it onto a running CommonUI stack. CommonUI is used through reflection, so projects without it work too.
- **CommonUI input**: `ui_input_audit` (missing action rows, Enhanced Input actions that never fire, duplicate actions, no input data asset), `ui_input_type` (switch a player to gamepad / mouse and keyboard / touch).
- **Localization**: `stringtable_list`, `stringtable_get`, `stringtable_set` (String Table assets, read back), `stringtable_compare` (missing, extra, empty, untranslated, format argument differences), `loc_culture` (preview another language).
- **Run the game**: `game_run` starts the game (this editor in `-game` mode, or a packaged exe) with a map URL, once per resolution. The URL is passed unchanged and checked against the game's own log; the run is stopped early when it does not match, or when a required test-mode line never appears. The reply gives a verdict from log patterns (PASSED / FAILED / CRASHED / TIMEOUT / …), only the log lines you asked for, and the new PNG files with their real size. `game_run_status` follows or stops a long run.
- **Compare images**: `image_compose` puts PNG files side by side in one labelled PNG (title, column and row labels), then reads the file back and compares every cell.
- **Gameplay Tags**: `gameplay_tags_list`, `gameplay_tag_add` (strict names, read back), `gameplay_tag_remove` (refused while assets use the tag).
- **Multiplayer tests on one machine**: `pie_actors` (what the server and each client see: count, net roles, owner, property values; waits for replication), `pie_net_emulation` (lag, loss, duplicates, reordering; profiles off / average / bad).
- **Measuring**: `class_measure` (size of a class or Blueprint without placing it), `screen_coverage` (how big an actor looks from a player's camera).
- **Optional build helper**: `Plugins/Enginewright/Scripts/ewtool.py` compiles the project while the editor is closed (waits for locked DLLs and names the process that holds them; UnrealBuildTool runs detached, so it keeps going when the caller is killed). Python 3, standard library only. You do not need it to use the plugin. See `docs/EWTOOL.md`.

## Changed

- `asset_rename` reports text and IDs that still name the old asset (a redirector cannot fix those); `dryRun` previews referencers and such text.
- `object_set` on a class default also updates placed instances and widget templates that still had the old default.
- `automation_list` / `automation_run` keep the editor at full speed while it is in the background (UE otherwise throttles it and tests time out).
- Every tool argument has a description in `describe` (checked by a test).

## Fixes

- The plugin builds in projects that use unity builds (helper names no longer clash).
- Adding and removing widgets keeps the Widget Blueprint's variable list consistent (no compiler ensure).

## Known issues and limits

- Tested on UE 5.8 Win64 only. The prebuilt zip contains Win64 binaries only.
- `ui_click` checks covering widgets at the UMG level; it does not press keys or gamepad buttons (use `pie_input`).
- `game_run` starts a new game process per resolution and stops it when the run is over; it does not attach to a game that is already running.
- `editor_restart` (close, build, reopen) is Windows-only.
- One editor per port (default 3100). Set `ENGINEWRIGHT_PORT` to run several editors.
- APIs may still change before 1.0.
