# Enginewright v0.3.1

Early preview. Supported: **Unreal Engine 5.8, Windows (Win64)**. Other engine versions, Mac and Linux are not tested yet.

## Install or update

1. Close the editor. Delete an older `Plugins/Enginewright` folder, then unzip into your project's `Plugins/` folder, so you get `<YourProject>/Plugins/Enginewright/Enginewright.uplugin`.
2. Open the project. The status bar (bottom right) shows `Enginewright :3100` with a green dot.
3. Click it to open the Enginewright panel and copy the config for your client (Claude Code, Codex, Cursor, VS Code, Hermes). The same files are in `<YourProject>/Saved/Enginewright/clients/`.
4. Ask your agent to call `doctor`.

Your token and port stay the same after an update.

## New

- **Status bar indicator**: `Enginewright :3100 (2)` at the bottom right. Green while the server listens, red when it is off or the port is in use; the number is the clients seen in the last 5 minutes. The tooltip shows the URL, the token state and the last call. Click it to open the panel.
- **Enginewright panel** (Tools > Enginewright): server on/off and port, the token (show, copy, make a new one), one-click client configs, the clients that talked to this editor, tool categories you can turn off, a read-only mode, the Output Log level, the last 15 calls with their result and time, and a `doctor` button.
- **Settings** in Project Settings > Plugins > Enginewright, saved per user and project (`EditorPerProjectUserSettings.ini`). The panel, Project Settings and `settings_set` change the same values, and changes apply at once.
  - Read-only mode refuses every tool that changes assets, the level, files or the editor (`READ_ONLY`). It is a guard against accidents, not a security boundary.
  - Turned-off tool categories are refused with `TOOL_DISABLED`; `describe` shows a tool's `category`.
- `editor_capture`: the main editor window or the Enginewright panel to a PNG.
- `doctor` also reports the server: version, URL, clients, read-only mode and turned-off categories.

## Fixes from a real game project

These came from using v0.3 on a game whose UI is written in C++:

- `widget_render` also takes C++ UserWidget classes (`/Script/MyGame.MyWidget`), not only Widget Blueprints. A widget that builds its tree in code is rendered the same way.
- `game_run` after Live Coding: a new game process loads the C++ modules on disk, not the patch in the editor's memory. `game_run` now refuses to start after a Live Coding patch (`LIVE_CODING_PATCHED`; rebuild with `editor_restart {"build": true}`, or pass `allowLiveCodingPatch: true`) and warns when C++ source changed after the last build. The `live_coding_compile` description says the same.
- `game_run` with a heavy editor level: the editor's realtime level viewports are paused while the game runs and restored after (`editorViewports: "keep"` to leave them), and a heavy level (Lumen, real-time sky light, volumetric clouds, many actors) is reported with a hint.
- `game_run` screenshot runs: `shotsExpected: n` ends the run when n new PNG files are written, with a `PASSED` verdict (`stopReason: SHOTS_DONE`) instead of a timeout. Useful with `-ExecCmds=HighResShot` in games that do not quit by themselves.

## Known issues and limits

- Tested on UE 5.8 Win64 only. The prebuilt zip contains Win64 binaries only.
- Turning the server off unbinds `/mcp`; the port itself stays open until the editor closes (Unreal's HTTP server has no per-port stop).
- A client is counted by its MCP session; clients that do not send `Mcp-Session-Id` are counted together.
- `editor_restart` (close, build, reopen) is Windows-only.
- APIs may still change before 1.0.
