# Enginewright v0.4.0

Early preview. Supported: **Unreal Engine 5.8, Windows (Win64)**. Other engine versions, Mac and Linux are not tested yet.

## Download

| File | SHA-256 |

| `EnginewrightMVVM-0.4.0-UE5.8-Win64.zip` (optional, MVVM tools) | `SHA256_MVVM_PLACEHOLDER` |

## Install or update

1. Close the editor. Delete an older `Plugins/Enginewright` folder, then unzip into your project's `Plugins/` folder, so you get `<YourProject>/Plugins/Enginewright/Enginewright.uplugin`.
2. Optional, only if the project uses MVVM (Epic's UMG Viewmodel plugin): unzip `EnginewrightMVVM-0.4.0-UE5.8-Win64.zip` into `Plugins/` too, so `Plugins/EnginewrightMVVM` sits next to `Plugins/Enginewright`, then enable `EnginewrightMVVM` in Edit > Plugins and restart. Skip it otherwise: Enginewright works without it.
3. Open the project. The status bar (bottom right) shows `Enginewright :3100` with a green dot.
4. Click it to open the Enginewright panel and copy the config for your client (Claude Code, Codex, Cursor, VS Code, Hermes). The same files are in `<YourProject>/Saved/Enginewright/clients/`.
5. Ask your agent to call `doctor`.

Your token and port stay the same after an update.

## Highlights

- Localization loop: `loc_gather` gathers, compiles and checks a target while the editor is open; `stringtable_compare` reads `.po` and `.locres` files; `game_run` takes a `culture`; `font_coverage` and `glyphMisses` find characters that would show as empty boxes.
- Game testing tools: `ui_key`, `pie_walk_to` and `pie_travel` drive a running game; `ui_state` shows only what the player can use; `ui_prompts` with `input_map_list` compares the on-screen hints with the real bindings.
- Game runs and images: `game_run` takes `shotNames`, `cvars` and `variants`; `image_stats` reports brightness, histogram and difference for each screenshot.
- Scene tools: `scene_dress` places hundreds of meshes in one undo step; `actor_preview` photographs an actor class without Play In Editor.
- MVVM: the `viewmodel_*` tools edit view models and bindings in an optional plugin.
- Reliability sweep: every tool was run on a real game project (RagnaCook) with 11 fixes.

## New

### Localization

- `stringtable_compare` reads a `.po`, `.locres` or CSV translation next to a String Table or CSV source. It reports translations made for an older source text and fuzzy entries.
- `loc_gather` / `loc_gather_status` gather, export, import, compile and check a localization target in one call. The commandlet works while the editor is open, and the verdict uses both exit codes.
- `game_run` `culture`: the game process gets the language, not only the editor.
- `font_coverage` lists the characters of a language or text that a Font asset or a `.ttf` / `.otf` cannot draw. `game_run` `glyphMisses` counts the characters Slate could not draw in the running game.

### Running and checking the game

- `game_run` `shotNames`: the run ends with `PASSED` / `SHOTS_DONE` when each named screenshot is written, and `SHOTS_MISSING` when the game ends without one.
- `game_run` `cvars`: console variables are sent as `-ExecCmds`, and unknown names are refused.
- `game_run` `variants`: the same run once per look, each screenshot with its stats and the diff to the first variant.
- `image_stats`: mean luma, luma histogram (16 bins), saturation, clipped black / white and, with `reference`, the brightness difference, mean absolute pixel difference, changed pixels and SSIM.

### Play In Editor and UI testing

- `ui_key`: a key or mouse button through Slate to the focused widget (for "press any key" panels), with an optional `focus` that moves user focus first.
- `pie_walk_to`: walks the pawn to a position with movement input, using a navmesh path when there is one, and reports `STUCK` / `TIMEOUT` with the last position.
- `pie_travel`: travels a running session to another map with URL options (`?game=...?listen`), checks the map and the options, and waits for the new map and the pawns.
- `ui_state` lists only what the player can use (visible, top page of its stack, page activated) and counts the rest. `includeHidden` shows the rest with `layer`, `top` and `hiddenReason`. Buttons carry `text`, `tooltip` and `label`, and `ui_click` finds a button by any of them.
- `input_map_list` lists the bound keys per action and device, from an asset or live from the player.
- `ui_prompts` compares the hints on screen (CommonUI action widgets and key-like texts) with those bindings and answers OK / MISMATCH / PROMPT_NOT_SHOWN / ACTION_NOT_BOUND per `check` entry.

### Save games

- `savegame_get` / `savegame_set`: read and write a SaveGame slot by reflection. A slot with a game footer or checksum needs the game's own save function (`saveFunction`).

### Scene tools

- `scene_dress`: ring, ellipse, line, grid or scatter of meshes around an actor or point, in one undo step, with seed, rotation and scale jitter, ground snap, overlap and avoid checks, instanced or separate actors, and DataTable export.
- `actor_preview`: builds an actor class like the game does (construction, BeginPlay, a few ticks) in an isolated preview world or temporarily in the open level, photographs it, and cleans up. No Play In Editor.

### MVVM

- `viewmodel_list`, `viewmodel_add`, `viewmodel_bind`, `viewmodel_unbind` and `viewmodel_remove` edit view models and view bindings of a Widget Blueprint, with conversion functions, one undo step, compile and read-back.
- The tools live in the optional `EnginewrightMVVM` plugin. Enginewright loads without it, never enables it, and the tools answer `MVVM_NOT_ENABLED` until both plugins are on.

### Editor panel

- The Enginewright panel shows its version label, a "What's new / Roadmap" button and a "Changelog" button (both open GitHub).

### Docs

- `docs/SUPPORT.md`, `CHANGELOG.md`, and the roadmap and request flow.

## Changed

- `ui_state` lists only visible widgets on the top page of their stack; `includeHidden` adds the rest.
- `ui_click` ignores closed and covered pages, and `AMBIGUOUS` names page and layer of each candidate.
- `asset_delete` says why an asset cannot be deleted, per asset, and the tool text explains `force`.
- `mesh_info` returns local bounds, size and the pivot offsets without spawning an actor.
- `blueprint_set_component_defaults` writes defaults of a component inherited from a C++ parent or an SCS component.
- `asset_import` takes `scale`, `rotation`, `translation` and `meshType` for static and skeletal meshes.
- Every tool argument has a type and a description.

## Fixes

- `game_run` `shotsFound` counted a screenshot copied from another folder twice (ER-09). It now counts each PNG once.
- `datatable_set_rows`: rows are checked on copies first, so a failed call no longer overwrites every row's `Name` field.
- `level_save` with `path`: the map is written inside `Content/` and registered with the asset registry at once; `.umap` files are found by `asset_exists` and `asset_delete`.
- `asset_delete`: a set of assets that only use each other is deleted referencer first, and String Tables no longer need `force`.
- `gameplay_tag_add` / `gameplay_tag_remove`: a tag ini created in the session is removed again with its last tag, and dropped from the editor's config cache.
- `game_run`: screenshots in `Saved/Screenshots` are moved into the run folder, not copied.
- `game_run`: a `/Game` map in `url` that does not exist answers `MAP_NOT_FOUND` with the closest maps, also in `dryRun`.
- `game_run`: the `dryRun` heavy-level warning matches what happens (viewports pause by default).
- `stringtable_compare`: a CSV source uses its file name as the namespace when the `.po` has that namespace, and a mostly-missing result warns.
- Every argument has a type and a description (80 had no description, 8 had no type).
- Descriptions now say that `key_audit` and `id_audit` answer `ok: false` on findings, that `automation_list` matches anywhere in the name, that a stopped `game_run` answers `RUN_NOT_PASSED`, and that `settings_set` writes a file in source control.
- `tests/smoke.py` with no editor prints one line instead of a urllib traceback.

## Tested

- `tests/run_all.py`: 19 suites, 856 checks, all passed on UE 5.8 Win64; `build` suite 15/15 (editor closed, compile, reopen).
- Every tool was called on RagnaCook, a UE 5.8 co-op game in development (330 calls): [RELIABILITY_0.4.md](../RELIABILITY_0.4.md).

## Known issues

- Tested on UE 5.8 Win64 only.
- `asset_find` returns an empty list without a warning for a folder that does not exist (planned for 0.4.1).
- There is no warning for asset names with non-ASCII letters (planned for 0.4.1).
- `loc_gather` writes the project's localization files. Run it on a clean working tree.
- The art import pipeline is not in this release (0.4.1).

## Tools

The client sees three meta tools: `search` (find a tool in plain words), `describe` (read its arguments) and `call` (run it). Behind them:

| Area | Tools |
|---|---|
| Objects | `object_get`, `object_set` |
| Assets | `asset_find`, `asset_exists`, `asset_references`, `asset_duplicate`, `asset_rename` (updates referencers, removes the redirector, reports text and IDs that still name the old asset; `dryRun` to preview), `asset_delete` (refuses assets still in use; says why per asset: which asset references it, open editor, unsaved changes; `force` explained in the tool text), `asset_save`, `asset_import` (texture, sound, font, mesh, while the editor is open; meshes take `scale`, `rotation`, `translation`, `meshType`) |
| Types and data | `enum_create`, `struct_create`, `type_info`, `datatable_create`, `datatable_get`, `datatable_set_rows`, `datatable_remove_rows`, `datatable_rename_row` |
| Blueprints | `blueprint_create`, `blueprint_info` (lists inherited C++ components too), `blueprint_set_component_defaults` (defaults of an inherited or Blueprint component, e.g. the Mesh of a Character; checked, read back, one undo step), `blueprint_compile`, `blueprint_add_variables`, `blueprint_remove_variables`, `blueprint_add_component`, `blueprint_remove_component`, `blueprint_graph_read`, `blueprint_add_node`, `blueprint_connect`, `blueprint_set_pin`, `blueprint_remove_node` |
| Materials, meshes, textures | `material_create`, `material_info`, `material_add_expression`, `material_connect`, `material_instance_create`, `material_instance_set`, `mesh_info` (local bounds, pivot offsets, size, without spawning an actor), `mesh_set_material`, `texture_info` |
| Enhanced Input | `input_action_create`, `input_context_create`, `input_map`, `input_unmap`, `input_context_info`, `input_map_list` (which keys are bound to which actions, grouped by action and device; from an asset, or live from the Play In Editor player with its applied contexts and priorities, runtime remaps included) |
| Level | `level_open`, `level_save`, `actor_find`, `actor_spawn`, `actor_set_transform`, `actor_delete`, `actor_bounds`, `world_trace`, `class_measure` (size of a class or Blueprint without placing it), `scene_dress` (set-dress an actor or a point with hundreds of meshes in one undo step: ring or ellipse, line, grid or scatter; several meshes with weights, seed, rotation and scale jitter, ground snapping, overlap and avoid checks; instanced or separate actors; can write the placements into a DataTable such as a game's dressing table), `actor_preview` (builds an actor class that sets itself up in code, construction script and BeginPlay, in a private preview world or temporarily in the open level, takes a PNG from a framed camera, a given one or the actor's own game camera (same layout as a game_run shot) and cleans up: no Play In Editor, no game_run) |

| Run the game | `game_run` (the game in `-game` mode or a packaged exe, with a map URL that is passed unchanged and checked against the game's log; one run per resolution; verdict from log patterns; only the log lines you ask for; new PNG files collected with their real size; screenshot runs can end by PNG count; refuses to start the old C++ code after a Live Coding patch; pauses the editor's realtime viewports while the game runs; `culture` starts the game with `-culture=<x>`; each run counts the characters Slate could not draw, `glyphMisses`; `shotNames` ends the run when the named screenshots exist; `cvars` and `variants` run the game with console variables, e.g. exposure, and report `image_stats` per screenshot), `game_run_status` (follow or stop a run), `image_compose` (PNG files side by side in one labelled image, read back), `image_stats` (mean brightness, luma histogram, saturation, clipped black / white, and the difference to a reference image) |

| Localization | `loc_gather` / `loc_gather_status` (gather, export, import, compile and check a localization target with the GatherText commandlet while the editor is open; verdict from both exit codes and the log), `stringtable_list`, `stringtable_get`, `stringtable_set` (String Table assets), `stringtable_compare` (source String Table or CSV vs a translation String Table, `.po` or `.locres`: missing, extra, empty, untranslated, format argument / rich text tag differences, translations of an older source text, fuzzy entries), `font_coverage` (characters of a language or a text that a Font asset or a .ttf / .otf cannot draw: empty boxes in the game), `loc_culture` (preview another language in the editor; a game started by `game_run` gets its language from `game_run`'s `culture`) |
| Gameplay Tags | `gameplay_tags_list`, `gameplay_tag_add` (to a tag ini, strict names), `gameplay_tag_remove` (refused while assets use the tag) |
| Build and tests | `live_coding_compile`, `editor_restart` (save, close, optionally build C++, reopen), `build_status`, `automation_list`, `automation_run` |
| Checks | `validate` (compile Blueprints, data validation, broken references, map check), `id_audit` (IDs used but never defined, and the reverse), `key_audit` (hard-coded input keys in C++ and Blueprints), `asset_search_text` |
| Editor | `editor_state`, `console_command`, `log_read`, `log_wait` (wait for a log line), `settings_get`, `settings_set`, `doctor`, `client_config`, `editor_capture` (the editor window or the Enginewright panel to PNG) |
| Multi-step | `batch` (atomic, rolls back on failure) |
